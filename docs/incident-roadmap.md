# Incident project scope and rollout
Approved direction: preserve AfterFall and add independent pathways by incident type. This setup records requirements and issues, not new running functionality.

1. Establish general+project instructions/source correspondence and falls baseline.
2. Specify incident routing; first complete wound input -> local draft -> review/edit/Copy.
3. Review severity/GP escalation fields, then evaluate API wording without changing facts.
4. Add local name protection with payload and restore tests; no raw fallback.
5. Implement foundation/rules/issue regression and actual CI gate evidence.
6. Specify infection and medication incidents separately.
7. Synthetic colleague trial and supported audience/API access planning.

Current implementation: independent six-section Fall, Wound and Infection questionnaires; seven fields in four output groups; optional server AI/narrow validator; separate page-memory pathway drafts, manual-edit protection and Copy gate. Wound/infection progress notes use paragraphs; falls eCase headings remain unchanged. See [pathway contract](incident-pathways.md) and issue delivery evidence for publication.
Planning: broader AI wording, local name substitution, medication pathway and colleague access. Severity is user-selected; automatic eCase scale conversion is not required.

General policies do not import ShiftBrief BNO/Leave functionality. No clinical record in issue examples. All feature changes require task-specific acceptance and testing evidence.
