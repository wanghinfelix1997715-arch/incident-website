# Incident project scope and rollout
Approved direction: preserve AfterFall and add independent pathways by incident type. This setup records requirements and issues, not new running functionality.

1. Establish general+project instructions/source correspondence and falls baseline.
2. Specify incident routing; first complete wound input -> local draft -> review/edit/Copy.
3. Review severity/GP escalation fields, then evaluate API wording without changing facts.
4. Add local name protection with payload and restore tests; no raw fallback.
5. Implement foundation/rules/issue regression and actual CI gate evidence.
6. Specify infection and medication incidents separately.
7. Synthetic colleague trial and supported audience/API access planning.

Current: six-section falls questionnaire, seven underlying document fields in four groups, optional server AI/narrow validator, manual-edit protection, Copy gate, page-memory data and owner-private access.
Planning: Wound questionnaire, incident routing, broader AI wording, local name substitution, other pathways, colleague access.
